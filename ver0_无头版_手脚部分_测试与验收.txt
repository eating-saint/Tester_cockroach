一、ver0 的目标
----------------------------------------------------------------------
先把"访问网页的手脚"组装完整：除了大模型决策，其他部分都要能用、能测。
  - 无头模式运行（Chrome 132 起 --headless 就是新版无头模式，旧版已移除）
  - 从读取 DOM 开始，一层一层往上搭
  - 大模型的位置先由"规则决策器"代替：输入 PageState，输出和以后大模型一样格式的决策 JSON。
    以后接入大模型时，只换掉决策器，其他代码不动。

不在 ver0 范围内：大模型、视觉坐标、鼠标轨迹（无头模式下看不到光标）、企业微信、平板、多设备。


二、ver0 包含的模块
----------------------------------------------------------------------
M1 浏览器管理  启动无头 Chrome（单独的用户目录 + 调试端口）、连接、关闭；崩溃后能检测到并重启
M2 页面导航    打开网址、后退、刷新；等待策略：load 事件 + "网络安静"（等待中的请求为 0 并保持 N 毫秒）+ 超时
M3 DOM 读取    可交互元素列表：角色 / 名称 / 文本 / href / 位置框 / 是否可见 / 是否可用；
               页面正文文本；iframe；Shadow DOM
M4 状态监控    网络（等待中 / 失败 / 状态码）、console 报错、加载阶段
M5 PageState   把 M3 和 M4 合成一个 JSON
M6 截图        整页截图和可视区截图；把元素框画到截图上（离线用 PIL 画，用于人工核对）
M7 动作        click(元素) / type(文本) / press(按键) / scroll / back；
               每个动作执行后检查有没有生效（URL、DOM 或焦点有没有变化）
M8 规则决策器  按用例里写的规则做决策，输出决策 JSON（ver1 换成大模型）
M9 任务树      create_child / complete / fail；同时只执行一个节点、深度上限、步数上限、
               子节点结束后只把摘要交回上一层
M10 日志与报告 每一步记录 PageState、决策、动作结果、耗时；汇总成报告


三、测试夹具：本地假网页（放在 fixtures\，用 python -m http.server 启动）
----------------------------------------------------------------------
每个页面的"标准答案"都事先写在对应的 expected.json 里。

F1 静态页     已知数量的按钮、输入框、链接（例如 5 / 3 / 8）
F2 隐藏元素   display:none、visibility:hidden、disabled、移出屏幕的元素各若干个
F3 动态加载   打开 2 秒后才通过 fetch 加载出列表
F4 慢请求     有一个请求 8 秒后才返回
F5 iframe     主页面嵌一个 iframe，iframe 里有按钮
F6 Shadow DOM Web Component 里有按钮
F7 表单       输入框 + 提交按钮，提交后显示"你输入了：xxx"
F8 懒加载     滚到底部才加载第二页内容
F9 故障页     一个链接指向 404；一个页面会在 console 里报错
F10 假搜索    搜索结果页分两个版本：一个有 reddit.com 链接，一个没有；
             reddit 假页面上有 5 条已知的评论预览文字
F11 跳转      点击后跳转到新页面，或者打开新标签页


四、测试任务与验收标准
----------------------------------------------------------------------
编号 | 测什么 | 通过标准
T01 | M1 启动和连接       | 10 次启动全部成功；/json/version 能访问；关闭后没有残留进程
T02 | M1 崩溃恢复         | 运行中强制结束 Chrome 进程 → 5 秒内检测到 → 自动重启 → 继续执行当前用例
T03 | M3 元素数量（F1）   | 提取到的按钮 / 输入框 / 链接数量和 expected.json 完全一致
T04 | M3 可见性（F2）     | 每个元素的"可见"和"可用"标记全部正确
T05 | M3 位置框（F1）     | 位置框和 getBoundingClientRect 的误差不超过 1 像素；元素框图人工核对无错位
T06 | M2 动态等待（F3）   | 等待结束时列表已经出现；不能用固定 sleep 来凑
T07 | M2 超时（F4）       | 超时设为 5 秒时：按时返回"超时"，并给出未完成的请求地址
T08 | M3 iframe / Shadow（F5、F6） | iframe 里和 Shadow DOM 里的按钮都能读到，也能点中
T09 | M7 表单（F7）       | 输入 → 提交 → 读到的结果文字和输入内容一致
T10 | M7 滚动（F8）       | 滚到底以后，第二页内容出现在元素列表里
T11 | M4 故障（F9）       | 404 被记为失败请求，状态码正确；console 报错被记录，内容一致
T12 | M7 跳转（F11）      | 能跟随新页面或新标签页，URL 正确；后退能回到原页面
T13 | M8 + M9 规则用例（F10 两个版本） |
      规则："出现 reddit 链接 → 点进去 → 读取所有评论预览"
      有 reddit 的版本：任务树为 母任务 → 子任务（点进去并读取），子任务 complete，5 条评论全部读到
      没有 reddit 的版本：子任务不创建，或者 complete 时写明"未出现"；不点任何链接
T14 | M9 步数上限         | 故意写一条永远达不成的规则 → 达到步数上限后强制 fail，程序不卡死
T15 | M9 上下文清理       | 子任务结束后，母任务的上下文里只剩摘要，没有子任务的 PageState
T16 | M10 报告            | 每条用例都有：通过或失败、每一步的 PageState 和决策 JSON、截图、耗时
T17 | 稳定性              | T03–T13 连续跑 50 轮，通过率 100%，内存没有持续上涨
T18 | 真实网站（只读）    | 朋友的点单网站：首页元素提取，人工抽查 20 个元素，名称和位置全部正确
T19 | 真实网站（动作）    | 朋友的点单网站测试环境：搜索菜品 → 加入购物车 → 购物车数量正确（由规则决策器驱动）
T20 | Bing 冒烟           | 搜一个词，结果列表能正确提取标题和链接；遇到验证码就暂停，等人工处理


五、验收办法
----------------------------------------------------------------------
1. 自动验收：运行 run_tests，自动对比 expected.json，输出一张表：
   编号 / 通过或失败 / 耗时 / 失败原因
   T01–T17 必须全部通过。
2. 人工验收：
   - 打开 T05 和 T18 生成的元素框图，肉眼核对
   - 抽查 T13 的任务树 JSON，确认结构和预期一致
   - 抽查 T19：用有界面模式（去掉 --headless）重跑一遍，确认动作和无头模式一致
3. ver0 完成的标准：
   T01–T17 自动验收全部通过，并且 T18–T20 人工验收通过。
   达到以后进入 ver1（接入大模型，替换 M8 规则决策器）。


六、交付物
----------------------------------------------------------------------
src\        M1–M10 代码

cases\      T13、T19、T20 的用例 YAML

run_tests   一键跑完全部自动验收
