# 控制面板（panel）Spec

日期：2026-11-12　状态：待整体审批　流程：mew-spec 阶段一

## 用词约定
- **决策方式**：规则决策（规则决策器 + 任务树 + DOM）/ 视觉大模型决策（ver1）。
- **浏览器显示方式**：无界面（Chrome 不开窗口）/ 有界面（Chrome 开真实窗口）。
- **自动化 Chrome**：被测试程序驱动的那个 Chrome，使用项目专用用户目录。
- **面板窗口**：显示面板界面（按钮、表单、任务树、预览小窗口）的程序窗口，和自动化 Chrome 是两个东西。
- **电脑端先行**：先把 Windows 电脑端做完并验收通过，再开始平板程序。

## 背景
- ver0 的"手脚"能力已经完整：驱动无界面或有界面的 Chrome，读取页面，执行点击、输入、按键、滚动、后退、读取；用例由规则决策器和任务树驱动，每一步留下截图和记录。
- 2026-11-12 新增了鼠标轨迹和两个可选干扰项（思考时间、滚轮乱动后回滚），参数要在 `config.yaml` 里改。
- 现在的问题：
  1. 调参数只能改配置文件、跑命令行、再翻报告，看不到实时效果；
  2. 40 套轨迹模板是凭经验定的参数，不是用户真实的手部习惯；
  3. 无界面运行时看不到浏览器在做什么，只能事后看截图；
  4. 只能在命令行里用，在 Windows 上不方便当软件用。
- **前提**：鼠标轨迹模块要先在 Windows 上通过全量回归（`pytest -q`、`run_tests.py` 的 T01–T17 和 T21）并提交，面板开发才开始。

## 目标
- **G1 控制面板**：本机运行的图形面板，集中完成调整设置、启动任务、观察运行过程。
- **G2 实时预览**：无界面时，面板小窗口实时显示自动化 Chrome 的画面，叠加鼠标轨迹和目标框；有界面时直接看 Chrome 的真实窗口，避免额外转画面。
- **G3 四种使用方式**：跑演示页对比不同设置的轨迹；跑用例文件；输入网址后在画面上指定目标让程序按当前设置去点；直接在预览里手动操作。
- **G4 过程可视化**：显示任务树、任务进度、当前步骤、正在等什么和已经等了多久。
- **G5 轨迹采集**：用"点目标"的方式采集用户自己的轨迹，来源有两种：仿真实网站的本地采集页、真实网站；鼠标和触控板分开标注，每种设备 8 个方向 × 每方向 5 条；可回看、删除、导出、导入。
- **G6 真实轨迹库**：鼠标轨迹可以从采集的样本里挑一条，变换到当前"起点 → 目标"上回放；面板里可在"真实轨迹库"和"40 套参数模板"之间切换并对比。
- **G7 Windows 软件**：打包成双击运行的 Windows 程序，自带窗口显示面板，不需要另装 Python。

本轮范围：控制面板与实时预览、轨迹采集、真实轨迹库回放、Windows 打包。平板和视觉大模型不在本轮（见"不做的事"）。

## 功能需求

### A. 面板与浏览器
- **F1 面板启动**
  - 面板在本机启动，只接受本机访问。
  - 打包版在自带窗口里打开面板；开发时也可以用普通浏览器打开本地地址。
  - 只允许运行一个面板：再次启动时提示"已在运行"，并把已有窗口切到前台。
- **F2 浏览器控制**
  - 状态灯：未启动、运行中、崩溃重启中、需要人工、已停止。
  - 启动、停止、重启三个按钮；无界面 / 有界面切换；显示本次崩溃次数。
  - 有任务在运行时，切换显示方式和停止浏览器的按钮不可用。
  - 有界面时，Chrome 真实窗口放在面板旁边，面板提供"调到前台"按钮；Chrome 窗口不嵌入面板。
- **F3 同一时刻只做一件事**
  - 演示、用例、指定目标、手动操作四种使用方式会用到浏览器，同一时刻只能运行一种。
  - 运行中其他三种的启动按钮不可用，面板显示"正在运行：xxx"；绕过界面直接发起的第二个启动请求也被拒绝。

### B. 观察
- **F4 实时预览**
  - 预览显示的是自动化 Chrome 的实时画面，不是另一个浏览器；手动操作时，预览里的输入会作为真实输入事件发给这个 Chrome。
  - 无界面时：推流到预览小窗口；点击打开新标签页时，预览跟着切换。
  - 有界面时：默认不推流，预览区显示提示和"调到前台"按钮；需要叠加时可以手动打开推流。
  - 叠加层可单独开关：元素框（带编号）、最近一次动作的目标框、计划轨迹、落点、过冲点、当前光标位置。叠加画在面板一侧。
- **F5 地址栏**：显示当前网址和标题；可输入网址打开、后退、刷新；有任务在运行时只读。
- **F6 等待与网络状态**
  - 显示当前在等什么（load、网络安静、动作后等待、思考时间、等待人工）、已等时长、超时上限。
  - 列出未完成请求、失败请求（含状态码）、console 报错、当前加载阶段。
- **F7 任务树与步骤**
  - 用例运行时显示任务树：每个节点的目标、状态、已用步数 / 上限、子任务摘要；当前活动节点高亮。
  - 步骤时间线：每步的决策、动作结果（是否生效、变化了什么）、CHECK / ANALYZE / EXECUTE 三段耗时。

### C. 设置
- **F8 设置调整**
  - 可调整：三个干扰项（轨迹、思考时间、滚轮乱动）的开关和参数；种子（固定或每次随机，界面显示本次实际种子）；轨迹来源（参数模板 / 真实轨迹库，选真实轨迹库时再选设备：鼠标、触控板或两者混合）；网络安静时长、导航超时；决策方式（规则决策；视觉大模型显示为灰色"未接入"，不可选）。
  - 修改在下一个动作开始时生效，正在执行的动作不受影响。
  - 保存前检查取值范围，超出范围不能保存并提示。
  - 可"保存为默认"（写回配置文件）和"恢复默认"。

### D. 四种使用方式
- **F9 演示页对比**
  - 在预览里打开演示页：中心起点、八个方向的按钮、一个小按钮；一键按当前设置依次点完。
  - 每次点击显示是否命中、计划耗时和实际耗时。
  - 保留上一轮轨迹，用另一种颜色叠加对比；可以用同一种子重放。
- **F10 用例运行**
  - 列出 `cases/` 里的用例，选择运行；需要夹具服务的用例自动启动夹具服务。
  - 运行中显示进度（当前步 / 步数上限）。
  - 点"停止"后，等当前动作结束再停，结果记为"用户停止"。
  - 结束后显示通过或失败、失败原因和报告链接。
- **F11 指定目标点击**
  - 输入网址打开页面；在预览画面上点一个元素（鼠标指向的元素框高亮），程序按当前设置去点它。
  - 显示动作结果：是否生效、变化了什么、轨迹。
- **F12 手动操作**
  - 切到"手动模式"后，预览里的点击、滚轮和键盘输入转发进自动化 Chrome。
  - 转发的输入直接送达，不经过轨迹模块。
- **F13 人工介入**
  - 在面板里运行用例时检测到验证码：面板提示"需要人工"，预览自动进入手动模式。
  - 用户在预览里处理，处理完点"继续"，用例接着跑；不切换到有界面，仍用同一个用户目录。
  - 命令行运行时保持原流程：切到有界面处理，处理完按回车继续。
  - 检测能识别真实验证框：reCAPTCHA、hCaptcha、Cloudflare Turnstile。
  - 用户点"继续"后，同一页面上已处理过的验证码不再重复转人工（验证通过后验证框常留在页面上，不能因此反复触发）。
- **F14 运行历史**：列出 `runs/` 下的历史运行（时间、标签、通过或失败），点一条可打开它的 report.html。

### E. 轨迹库、打包、用户目录
- **F15 轨迹采集**（两种来源，每条样本标注来源）
  - 每组采集前先选设备：鼠标或触控板。
  - 每次采集：用户先点起点，再移动到目标并点击。记录从点起点到点目标之间所有指针位置和时间，以及起点、目标框、落点、设备、屏幕缩放比例、采集时间、来源。
  - **本地采集页**（负责把 8 个方向采均衡）：
    - 在面板窗口里，不在自动化 Chrome 里。
    - 做成真实网站的样子：搜索框、导航栏、结果列表、商品卡片、"加入购物车"按钮等；每组布局随机变化，控件大小覆盖 16–80 CSS 像素。
    - 按 8 个方向轮流出题，从页面控件里挑一个距离起点 150–600 CSS 像素的作为目标。
  - **真实网站采集**（补充）：
    - 在有界面的自动化 Chrome 里打开网址，用户在 Chrome 真窗口里操作。
    - 进入采集模式后，才往当前页面的隔离环境注入一段只监听指针移动和点击的脚本：不改页面内容，不阻止任何事件；退出采集模式即撤除。
    - 面板从页面的可点元素里挑目标，优先补样本少的方向；某方向没有合适元素时跳过并提示。
    - 目标点击照常生效；页面因此跳转时，样本照常保存，面板提示并可一键后退。
    - 样本额外记录网址的域名，不记录页面内容。
  - 进度按"8 个方向 × 5 条"的格子显示，每种设备单独一张，格子里分别显示两种来源的条数。
  - 自动作废并提示原因：没点中目标、指针中途离开采集区（本地采集页）或页面视口（真实网站）、耗时超过 5 秒、记录的点太少。
  - 管理：回看（列表、单条画图、动画回放）；删除单条；补采（只出未满的格子）；导出为一个文件；导入（可选合并或替换，合并时去重）。
- **F16 真实轨迹库回放**
  - 轨迹来源为"真实轨迹库"时，每次移动：按方向和所选设备，用种子从库里挑一条样本；平移、旋转、缩放到当前"起点 → 落点"；时长按距离比例调整，并限制在 180–1100 毫秒（和参数模板相同）。
  - 落点规则不变：目标框内的随机点。
  - 库里该方向没有样本时，这一次退回参数模板，并在记录里注明。
  - 每步记录写明轨迹来源和样本编号。
  - 命令行运行时同样可以通过配置切换轨迹来源。
- **F17 Windows 程序**
  - 打包成双击运行的程序，不需要另装 Python。
  - 第一次运行自动查找 Chrome，找不到时提示用户设置路径。
  - 用户目录、运行记录、轨迹库、配置放在程序旁边的数据目录，升级程序不丢数据。
  - 关闭窗口时同时关闭自动化 Chrome，不留残留进程。
- **F18 专用用户目录保留状态**
  - 在自动化 Chrome 里登录的账号、Cookie、网站设置，下次启动仍在；命令行和面板用同一个目录。验证码人工处理后拿到的 Cookie 同样保留。
  - 面板显示这个目录的位置和占用空间，提供"清空"按钮：清空前二次确认，浏览器运行时不可用。
  - 和日常 Chrome 完全隔离，不导入、不读取日常浏览器的任何数据。

## 非功能需求
- **N1 只限本机**：面板服务只监听本机地址；不是来自面板页面本身的请求一律拒绝（防止其他网页调用本地服务）；手动操作转发的输入只接受来自面板页面的。
- **N2 隔离**：三者的用户数据互不相通——日常浏览器（程序不碰）、自动化 Chrome（项目专用用户目录）、面板窗口（系统自带的 WebView2，数据不保留，只能打开本机面板地址，不能访问外网）。
- **N3 不改变 ver0**：面板是可选外壳，核心模块不依赖面板；命令行用法、用例格式、原有验收行为不变；轨迹来源默认仍为参数模板；每加一块功能后，ver0 全量回归（T01–T17、T21）仍全部通过。
- **N4 预览不干扰测试**：开不开预览，等待判定、元素坐标、动作是否生效都一致；推流不改变视口尺寸，不计入"网络安静"的请求统计；测试运行时不往被测页面注入任何东西。唯一例外是真实网站采集模式（F15），只在采集期间、在隔离环境里注入只读监听脚本。
- **N5 实时性**（在用户电脑上实测，8 代 i5）：演示页轨迹运动期间，预览帧率不低于本机推流基准测试测到的上限的 90%（云端 2 核无显卡环境实测上限 60 帧/秒，所以预计标准约为 54 帧/秒）；页面变化后 0.1 秒内显示到预览；状态信息至少每 0.5 秒刷新；从双击启动到界面可用不超过 10 秒。
- **N6 可重放**：种子、轨迹库、设置相同时，轨迹点完全一致；从库中挑样本也由种子决定；记录写明种子、轨迹来源、样本编号。
- **N7 稳定性**：自动化 Chrome 崩溃时面板不崩，显示状态并恢复；面板页面刷新或重连后恢复显示当前状态；在面板里连续跑 20 次用例，内存不持续上涨。
- **N8 可追溯**：面板发起的演示、用例、指定目标运行都在 `runs/` 下有独立运行目录和报告，标签注明来自面板；手动操作不按步骤记录，但人工介入的开始和结束时间写进报告。
- **N9 轨迹数据**：样本存为本地文件，格式人能直接读，带版本号；只记录采集区（本地采集页）或页面视口（真实网站采集模式）内的指针数据；真实网站样本只多记网址域名，不记页面内容。
- **N10 屏幕缩放**：Windows 显示缩放 100%、125%、150% 下，预览点选目标、采集坐标、回放落点都正确；轨迹统一用 CSS 像素保存。
- **N11 环境与依赖**：Windows 11、系统自带 Chrome（≥136）；新增依赖只有 aiohttp、pywebview，打包另加 PyInstaller；面板前端不用构建工具，不从网上加载第三方前端库，断网可完整使用；界面中文。
- **N12 用途定位**：轨迹模块和干扰项只用于已授权的测试对象，不用于规避网站的人机识别；设置页写明这一定位；遇到验证码一律转人工，由用户亲手完成，程序不做任何自动破解；真实网站采集只用于已授权的网站；不为了测试故意在外部网站上触发验证码。
- **N13 可移植**：面板读取页面、执行动作只通过现有核心模块（CDP）完成，不依赖 Windows 特有的窗口机制，以便平板以后复用读 DOM 和动作的代码。

## 不做的事
- 平板端（Termux 可行性验证、平板版本）：电脑端完成并验收通过后另开一轮。
- 视觉大模型决策（ver1）：面板只留"决策方式"切换位，显示"未接入"。
- 自由手画轨迹、从日常使用中后台采集轨迹、用系统级鼠标钩子采集。
- 自动区分鼠标和触控板（由用户手动选）。
- 用采集数据训练模型或生成新轨迹（只做样本变换回放）。
- 键盘打字节奏模拟。
- 触屏手势（点按、滑动）。
- 远程访问面板（局域网、公网）、登录、多用户。
- 同时运行多个浏览器或多个任务、多个用户目录。
- 在面板里编辑用例、把操作录制成用例。
- 在面板里重做报告查看器（只打开现有 report.html）。
- 安装程序、自动更新、代码签名（只出能双击运行的程序文件夹）。
- macOS、Linux 打包。
- 修改 ver0 的等待策略和动作逻辑。验证码检测只按 F13 补两点：识别真实验证框、点"继续"后不重复转人工。
- 把 Chrome 窗口嵌入面板。
- 打包内置浏览器内核（迁移到 Edge 内核以后再说）。
- 从日常浏览器导入 Cookie 或登录状态。
- T18、T19（朋友的点单网站）。

## 验收标准

验收方式：**自动** = 脚本跑完给出通过/失败；**自动+目视** = 脚本判定后，还要人看一眼截图或画面；**人工** = 必须用户亲手操作。

| AC | 对应 | 方式 | 验收内容 |
|---|---|---|---|
| AC0 | 前提 | 自动 | 开发开始前，在 Windows 上 `pytest -q` 全过，`run_tests.py` 的 T01–T17、T21 全过，轨迹改动已提交 |
| AC1 | F1、N1 | 自动 | 启动后面板可用；从本机其他端口的网页向面板服务发请求被拒绝；用局域网 IP 访问连不上；再启动一次提示"已在运行"，原窗口到前台 |
| AC2 | F2、N7 | 自动 | 启动、停止、重启时状态灯正确变化，停止后无残留 Chrome 进程；任务运行中切换显示方式和停止按钮不可用；运行中强制结束 Chrome，5 秒内状态灯变为"崩溃重启中"，随后恢复"运行中"，崩溃次数加 1，面板本身不崩 |
