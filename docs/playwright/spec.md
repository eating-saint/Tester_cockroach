# Playwright 驱动方案 Spec

## 背景
hands 手脚层目前用自写原生 CDP 驱动本机 Chrome（ver0），控制面板（panel）在其上提供预览、设置、运行任务、人工介入、轨迹采集。用户希望新增一套用 Playwright 实现的驱动，与 CDP 方案并存、可切换，用来比较两种方案；之后再讨论设备级方案。

已有能力中与驱动无关的部分（决策、规则决策器、任务树、记录与报告、轨迹与干扰项、验证码判定、配置、面板的大部分、全部用例与夹具）保持不变、两种方案共用，不重复实现。

## 目标
- 能用 Playwright 方案完成现有用例：读取页面（元素列表 + 截图）、点击、输入、按键、滚动、导航、后退、读文本、读链接、新标签页跟随、跨源 iframe、Shadow DOM、等待"网络安静"与超时、崩溃重跑、验证码转人工。
- 命令行、配置文件、面板三处都能选择驱动。
- 给出两种方案的性能对比。

## 功能需求
- F1 驱动选择：配置文件可设驱动为"CDP"或"Playwright"，默认 CDP；命令行可临时指定，优先于配置文件。选 Playwright 但未安装 Playwright 时，给出明确的中文提示（含安装命令）并退出，不回落到 CDP。
- F2 浏览器启动：Playwright 方案使用本机同一个 Chrome 和同一个专用用户目录，支持有界面 / 无界面；不另下载浏览器内核；不去掉 Playwright 默认的自动化标记。
- F3 读取页面：元素列表以 Playwright 自带的无障碍快照为准（角色、名字、视口坐标、元素引用），覆盖主页面、同源与跨源 iframe、开放与封闭 Shadow DOM（封闭的在页面加载前强制改为开放）；补齐所在块文字、链接地址、输入框的值、是否禁用、是否在视口内等字段，使规则决策器无需改动即可使用。不要求与 CDP 方案的元素列表逐条一致。
- F4 动作：点击（含鼠标轨迹与干扰项）、输入、按键、滚动、导航、后退、刷新、读文本、读链接，均用 Playwright 原生的鼠标、键盘、页面接口完成；动作前后照旧判断是否生效。
- F5 等待：导航与动作后等待"网络安静"，规则与 CDP 方案相同（安静时长、长连接与后台请求的排除规则、总超时）；超时时返回"超时"及未完成的请求地址。
- F6 页面跟随：新标签页打开时自动切换到新页；页面崩溃或浏览器断开时判为崩溃，当前用例从头重跑。
- F7 验证码：检测规则不变；命令行下转人工时切到有界面、人工处理后回到原显示方式继续，与 CDP 方案一致。
- F8 面板：设置页可切换驱动；有任务运行时切换禁用；切换后重启浏览器。状态、预览推流、预览上的手动输入、人工介入、导航按钮在 Playwright 方案下可用（推流与手动输入可通过 Playwright 提供的 CDP 会话复用现有实现，后续将整体替换为远程推流）。
- F9 验收脚本：一键验收与面板验收脚本可指定驱动运行。
- F10 性能对比：输出两种方案的对比表：浏览器启动耗时、一次读取页面耗时、一次点击耗时、50 轮稳定性测试的总耗时与内存变化。

## 非功能需求
- N1 向后兼容：不选 Playwright、不安装 Playwright 时，现有全部行为、测试结果与现在完全一样；Playwright 作为可选依赖，核心依赖不变。
- N2 不重复：与驱动无关的模块两种方案共用一份代码；驱动相关部分通过统一接口接入，上层（用例执行、动作执行、决策、面板）不感知具体驱动。
- N3 坐标统一为 CSS 像素，与现有约定一致。
- N4 不做规避人机识别（不改指纹、不藏自动化痕迹、不轮换 IP）；遇验证码一律转人工。

## 不做的事
- Playwright 方案不做真实网站轨迹采集（本地采集页不受影响，它是面板自己的页面）。
- Playwright 方案不做有界面时 Chrome 窗口的位置摆放（窗口留在 Chrome 自己的位置，仍可调到前台）。
- 不要求两种方案的元素列表逐条一致，不做元素级对比报告。
- 焦点模拟若 Playwright 未内置，不另行补；无界面下滚轮若不生效，记为已知差异，不为此改走 CDP。
- 不做远程推流、设备级方案、平板。
- 默认驱动不改，仍为 CDP。

## 验收标准
- AC1（F1、N1）：不装 Playwright、默认配置下，`pytest`、一键验收（T01–T17、T21）、面板验收（自动项）结果与现在相同；配置或命令行选 Playwright 而未安装时，看到中文提示并以非零状态退出。
- AC2（F2–F7、F9）：一键验收在 Playwright 驱动下 T01–T17、T21 全部通过（T08 含跨源 iframe，T06/T07 等待与超时，T02 崩溃重跑）；滚轮相关项如不通过，须在验收记录中说明原因并经用户确认列为已知差异。
- AC3（F3）：新增一个含封闭 Shadow DOM 按钮的夹具，Playwright 驱动下能在元素列表中看到并点中该按钮。
- AC4（F7）：Playwright 驱动下跑假验证码页用例：命令行转人工后，处理完能继续并通过。
- AC5（F8、F9）：面板验收在 Playwright 驱动下除 P30（真实网站采集）外的自动项全部通过；面板设置页能看到驱动选项，任务运行中切换请求被拒，切换后状态显示新驱动。
- AC6（F4）：Google 用例 g02 在 Playwright 驱动、有界面下跑通一次（遇验证码人工处理）。
- AC7（F10）：生成性能对比表，两种方案各项数值齐全。
