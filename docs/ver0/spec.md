# ver0 无头版"手脚" Spec

## 背景

* 项目目标：本地视觉大模型做决策、确定性脚本执行的自动化网站测试系统，最终测试对象是朋友的点单网站（已授权）。
* 当前状态：仅有三份方案文档（技术方案细则\_v1、调通方案\_网站测试\_v1、ver0\_无头版\_手脚部分\_测试与验收），无代码。本机 Windows 11、Python 3.12、Chrome 156。
* ver0 定位：先把"访问网页的手脚"组装完整，大模型的位置由规则决策器代替，输出与大模型相同格式的决策；ver1 只替换决策器。

## 目标

* G1：通过自写原生 CDP 驱动 Chrome，默认无头，可切换有界面。
* G2：读取页面可交互元素（含 iframe、Shadow DOM）与页面状态（网络、console、加载阶段），合成统一 PageState。
* G3：执行点击、输入、按键、滚动、后退等动作，并判断动作是否生效。
* G4：规则决策器 + 任务树驱动一条完整用例，产出带证据的测试报告。
* G5：用本地假网页 F1–F11 和标准答案对上述能力一键自动验收（T01–T17），并用 Bing 冒烟（T20）验证真实网站基本可用。
* G6：浏览器崩溃可检测、自动重启，当前用例从头重跑。

本轮范围：M1–M10 + T01–T17 + T20。T18、T19 留到后续。

## 功能需求

* F1 浏览器管理：以项目专用用户目录、调试端口启动 Chrome，默认无头、可配置有界面；确认调试端口可访问后再连接；关闭时全部进程退出无残留；持续检测存活，进程消失或连接断开后 5 秒内确认崩溃并自动重启、重连。
* F2 页面导航与等待：打开网址、后退、刷新。统一等待策略：load 事件 + "网络安静"（等待中请求数为 0 并保持可配置时长）+ 总超时；禁止用固定时长 sleep 凑等待。超时时返回"超时"结果并列出未完成请求的地址。
* F3 DOM 读取：提取可交互元素（按钮、输入框、链接、下拉框等），每个元素含角色、名称、文本、链接地址、位置框（CSS 像素，相对主页面视口）、是否可见、是否可用；iframe（含跨源 iframe）和 Shadow DOM 内元素同样提取，位置框换算到主页面坐标；提取页面正文文本。
* F4 状态监控：通过订阅浏览器事件持续统计等待中请求、失败请求（含状态码和地址）、console 报错（含内容）、当前加载阶段，包括所有 iframe 内产生的请求和报错；不向页面注入代码。
* F5 PageState：把网址、标题、元素列表、正文文本、监控状态、截图引用合成为结构化数据，可存为 JSON。
* F6 截图：可视区截图与整页截图；可离线把元素位置框和编号画到截图上，生成人工核对用的标注图。
* F7 动作：点击指定元素、输入文本、按键、滚动（按距离或到底）、后退；每个动作后检查是否生效（网址、DOM 或焦点有无变化），未生效要明确标出；点击打开新标签页时自动跟随。
* F8 规则决策器：输入当前 PageState 和用例规则，每次输出一个决策，格式与大模型一致（决策类型、理由、工具名、参数）；只能调用已注册工具；格式不合法则重新生成，最多 3 次。
* F9 任务树：创建子任务（目标 + 完成条件）、完成（结果摘要）、失败（原因）。程序保证：同一时间只有一个节点执行；子节点未结束父节点不能继续；树深度有上限；每个节点步数有上限，用完强制失败；子节点结束后删除其上下文，只把摘要交回父节点；每次运行保存任务树变化过程。
* F10 日志与报告：每一步记录 PageState、决策、动作结果、截图、耗时；每条用例输出通过或失败、失败原因、每步记录；汇总成报告。
* F11 用例执行与崩溃恢复：从用例文件读取用例并顺序执行，一条失败不影响后续；执行中浏览器崩溃，重启后当前用例从头重跑，重跑次数有上限，崩溃次数记入报告。
* F12 人工介入：检测到验证码或人机验证时进入"需要人工"状态，保存截图，在命令行提示用有界面模式、同一用户目录处理；人工按回车后重新加载页面继续。
* F13 测试夹具与一键验收：提供 F1–F11 本地假网页及各自标准答案，经本地 HTTP 服务提供；一键运行全部自动验收，输出"编号 / 通过或失败 / 耗时 / 失败原因"表。

## 非功能需求

* N1 确定性：底层动作和等待全部由明确条件触发，无隐式自动等待或自动重试；同样输入产生同样动作序列。
* N2 不侵入页面：读状态靠事件订阅或只读查询；必须在页面取值时只读不写，不常驻脚本。
* N3 决策器可替换：决策器只通过"PageState 进、决策出"约定与其余部分交互，ver1 换大模型时其他模块不改代码。
* N4 驱动接口平台无关：动作接口按抽象动作设计（点击可对应点按、滚动可对应滑动）；全系统坐标统一为 CSS 像素，换算只在驱动层内部。
* N5 隔离：只使用项目专用用户目录，不碰日常 Chrome 配置和进程。
* N6 稳定性：T03–T13 连续 50 轮通过率 100%，进程内存不持续上涨。
* N7 可追溯：每次运行的全部产物（截图、PageState、决策、任务树、报告）存于本次运行专属目录，互不覆盖。
* N8 外部网站礼貌：访问 Bing 时请求间隔留长；不做任何破解验证码或规避检测的处理。
* N9 环境：Windows 11、Python 3.11+、系统 Chrome（136+）；依赖仅限 websockets、httpx、pillow、pyyaml、pytest。

## 不做的事

* 大模型接入、视觉坐标识别、坐标吸附（ver1）
* 鼠标轨迹模块、Overlay 实时高亮（后续版本）
* OCR
* T18、T19 朋友点单网站的元素提取与下单动作（后续单独一轮）
* 原生 App / 平板驱动（Android、iOS、Windows）、多设备、Master/Agent 架构
* 企业微信人工通道、frp
* PostgreSQL、Redis（ver0 用本地文件存储）
* 多账号 BrowserContext 隔离（ver0 只用一个默认上下文）
* 网络身份（指纹、IP）
* 自动破解验证码
* 报告视觉美化（JSON + 简单 HTML 页即可）

## 验收标准

* AC1（F1 / T01）：连续启动—连接—关闭 10 次全部成功；每次可访问调试端口版本信息；关闭后无残留 Chrome 进程。
* AC2（F1、F11 / T02）：运行中强制结束 Chrome → 5 秒内检测到 → 自动重启 → 当前用例从头重跑并最终通过；报告记录 1 次崩溃。
* AC3（F3 / T03）：F1 静态页提取到的按钮、输入框、链接数量与标准答案完全一致。
* AC4（F3 / T04）：F2 隐藏元素页每个元素的"可见""可用"标记全部正确。
* AC5（F3、F6 / T05）：F1 静态页位置框与页面 getBoundingClientRect 误差 ≤ 1 像素；生成元素标注图，人工核对无错位。
* AC6（F2 / T06）：F3 动态加载页，等待返回时列表已出现，过程中无固定 sleep。
* AC7（F2、F4 / T07）：F4 慢请求页、超时 5 秒：约 5 秒（误差 1 秒内）返回"超时"，并列出慢请求地址。
* AC8（F3、F7 / T08）：F5 中同源 iframe、跨源 iframe 和 F6 Shadow DOM 内的按钮都能读到，位置框误差 ≤ 1 像素，点击后页面显示的点击结果与标准答案一致；并确认跨源 iframe 确实运行在独立进程中。
* AC9（F7 / T09）：F7 表单输入 → 提交 → 读到的结果文字与输入内容一致。
* AC10（F7 / T10）：F8 懒加载滚到底后，第二页内容出现在元素列表里。
* AC11（F4 / T11）：F9 故障页的 404 被记为失败请求且状态码为 404；console 报错被记录且内容与标准答案一致。
* AC12（F2、F7 / T12）：F11 能跟随新页面和新标签页，网址正确；后退能回到原页面。
* AC13（F8、F9 / T13）：F10 有 reddit 版本——任务树为 母任务 → 子任务，子任务完成，5 条评论全部读到；无 reddit 版本——不创建子任务或完成时写明"未出现"，且不点任何链接。
* AC14（F9 / T14）：永远达不成的规则在步数上限处被强制失败，程序正常结束不卡死。
* AC15（F9 / T15）：子任务结束后，母任务上下文只含子任务摘要，不含子任务 PageState。
* AC16（F5、F10 / T16）：每条用例都有通过或失败、每步 PageState 和决策 JSON、截图、耗时；PageState 能完整存为 JSON。
* AC17（N6 / T17）：T03–T13 连续 50 轮通过率 100%；第 50 轮内存较第 5 轮增长不超过 20%。
* AC18（F12 / T20）：Bing 搜一个词，结果列表正确提取标题和链接（人工核对）；如遇验证码，进入"需要人工"状态、保存截图并提示，人工回车后能继续。
* AC19（F13）：一条命令跑完 T01–T17，输出编号 / 通过或失败 / 耗时 / 失败原因表，T01–T17 全部通过。
* AC20（F10、N7）：每次运行产物位于独立运行目录，两次运行互不覆盖。
