# 鼠标轨迹模块与可选干扰项

日期：2026-11-12　代码：`src/hands/humanize.py`（算法）、`src/hands/actions.py`（接入动作）

## 1. 用途和边界
- 用途：在**已授权的测试对象**（朋友的点单网站、本地假网页）上模拟真实用户的操作节奏，检查页面在鼠标经过、停顿、滚动后是否仍然正常。
- 默认全部关闭。关闭时，事件序列和 ver0 完全一样，原有验收不受影响。
- 所有随机都来自带种子的随机数，写进报告；用同一种子可以逐点重放，测试结果可复现（不违反 spec N1"确定性"）。
- 不用于规避网站的人机识别。遇到验证码仍按原设计暂停，转人工处理。

## 2. 三项功能
| 项 | 配置键 | 做什么 |
|---|---|---|
| 鼠标轨迹 | `humanize.mouse` | 点击、输入、滚动前，鼠标沿轨迹移到目标框内的随机落点，再按下 |
| 思考时间 | `humanize.think` | 每个动作前按概率停顿一段随机时间 |
| 滚轮乱动 | `humanize.scroll_jitter` | 每个动作前按概率随机滚 1–3 下，停一会儿，再滚回原位（误差 ≤1 像素） |

## 3. 轨迹算法
1. **方向**：起点到落点的角度，按 45° 一档归入 8 个方向（0=右，2=下，4=左，6=上）。
2. **模板**：每个方向 5 套（平滑弧线、快速直线、大弧线、S 形、中途犹豫），共 40 套，每次随机抽一套。往右、往下时弧线偏一侧，往左、往上时偏另一侧；竖直方向弧度略小。
3. **主段**：三次贝塞尔曲线走到过冲点，叠加首尾为 0 的轻微横向抖动。
4. **过冲回拉**：模板允许、且距离超过 40 像素时，按概率先冲过落点 4–30 像素，再用一小段曲线拉回。
5. **落点**：目标框内偏向中心的随机点，离边缘至少留 20%；框小于 4 像素时取中心。
6. **时长**：Fitts 定律 140 + 110·log2(1 + 距离/目标尺寸) 毫秒，乘 0.85–1.2 的随机系数，限制在 180–1100 毫秒。每 16 毫秒一个点，按时间戳逐点发送 `mouseMoved`。
7. **光标位置**：每条用例从视口内一个随机位置出发，之后记住上一次的落点。

## 4. 滚轮乱动的细节
- 只往有空间的方向滚：在页面顶部就往下，在底部就往上；两边都滚不动就跳过。
- 回滚按实际偏移量反向滚，最多校正 4 次，直到误差 ≤1 像素。
- 乱动发生在动作的"前指纹"之前，所以它引起的变化（比如懒加载出新内容）不会被算成动作的效果。

## 5. 怎么用
```
python -m hands run cases/t13_reddit_yes.yaml --humanize              # 三项全开
python -m hands run cases/t13_reddit_yes.yaml --humanize-only mouse   # 只开轨迹
python -m hands run cases/t13_reddit_yes.yaml --humanize --seed 1234  # 固定种子，可重放
python run_tests.py --humanize                                        # 整轮验收都开着跑
```
也可以在 `config.yaml` 的 `humanize` 段长期打开，并调整概率、时长、幅度。

## 6. 记录和回放
- 每一步的 `action.json` 里有 `trajectory`（起点、落点、目标框、方向、模板、过冲点、全部轨迹点）和 `disturbances`（思考时长、滚动各段、回滚误差）。
- 开启轨迹时，每步还会存 `trajectory.png`：鼠标到位那一刻的截图，画上蓝色目标框、由绿到红的轨迹线、绿圈起点、橙叉过冲点、红点落点。无头模式看不到光标，就靠这张图回放。
- `report.html` 顶部显示运行种子，每步一列"轨迹"链接和干扰项摘要。各用例的种子写在 `report.json` 的 `humanize_seed`。

## 7. 验收
- 单元测试 `tests/unit/test_humanize.py`（10 项）：方向划分、40 套模板、500 条随机轨迹的落点都在框内且终点精确、时间单调、过冲距离上限、同种子同轨迹、轨迹确实弯曲、滚轮计划、配置开关。
- 验收 T21（夹具 F12 + F5）：中心到 8 个方向各点一次，再点 12×12 像素的小按钮，页面记录的点击坐标都在按钮内，每次点击前页面至少收到 5 个 mousemove；滚轮乱动每次都发生并回到原位；只开轨迹时同种子两遍逐点一致、换种子不同；跨源 iframe 里的按钮也能点中。

## 8. 这次顺带的改动
- `page.py` 接管页面时开启 `Emulation.setFocusEmulationEnabled`：部分无头环境里页面被当成"没有焦点"，滚轮事件会一直等不到确认（在 Linux 的 Chrome for Testing 153 上 T10 因此卡住）。开启后页面始终按有焦点处理，窗口被遮挡时也更稳。
- `browser.py`、`config.py`、`tests/acceptance/common.py` 增加了 Linux 分支（进程查找、结束进程、找 Chrome、内存读数）。Windows 的代码路径没有变。
- T06 的"禁止固定 sleep"扫描加入 `humanize.py`，只放行标注了 `humanize-pacing` 的节奏控制行。
