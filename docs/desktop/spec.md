# 桌面驱动与关联展开任务 Spec

日期：2026-11-14　状态：待审批（阶段一）　流程：mew-spec
本章做两件事：①电脑端第三种执行后端（桌面驱动）；②关联展开任务树（与驱动无关）及其在电脑面板上的随时改树。**手机控制端**（把面板上的查看、改树、暂停恢复取消、确认搬到手机）是下一章；**平板**不做。

## 用词约定
- **桌面驱动**：本章新增的第三种驱动，与 CDP、Playwright 并列、可切换。
- **代理窗口**：桌面驱动在用户默认 Chrome Profile 里新开的那一个窗口，Agent 只在这个窗口里操作。
- **无障碍树**：Windows 系统的界面自动化接口读到的 Chrome 页面结构（角色、名称、位置框、链接、输入值等），由 Chrome 自己提供给系统。
- **网格兜底**：无障碍树读不到可用元素时，在截图上叠一层带编号的网格，让模型选格子。
- **人工输入 / 注入输入**：人手动的鼠标键盘操作 / 程序发出的鼠标键盘操作，系统能区分这两种来源。
- **需确认动作**：不硬拦、但要先暂停等用户点"允许一次 / 拒绝"的动作。
- **关联展开任务**：从一组"键 <值, 值, …>"出发，逐个搜索、按关联条件增减节点，直到全部节点成为末端叶子的任务类型。
- **键**：下面挂着若干值的词，在树上是分叉。**值**：挂在某个键下面的词。同一个词可以出现在多个键下面，每次出现都是一个独立节点。
- **末端叶子**：已经搜过、且没有发现满足关联条件的新连接的值节点。**暂定叶子**：搜过一次、暂时没有新连接，但所在的键还没跑完的值节点。
- **任务类型定义**：一份事先写好的用例文件，写明初始键值组、起始词、搜索方式、去哪里找候选词、关联条件、次数上限、输出方式。由用户与 Claude 在开发对话中共同编写；运行时的 4b 模型只增减节点，不设计任务形态。
- **一次消耗**：一次搜索或一次打开阅读一个页面，计为 1 次。

## 背景
- 已有：ver0 手脚层（CDP、Playwright 两种驱动，同一套驱动接口）；ver1 视觉大模型决策（描述调用 + 带编号标注图选号、坐标取自 DOM、兜底拦截、内容抽取、重复动作检测）；任务树（母子任务、步数上限、摘要回传）；鼠标轨迹与真实轨迹库；控制面板（预览、设置、运行、人工介入）；验证码转人工。ver1 已验收（41/42），E2 在调试中。
- 两种现有驱动都用独立的测试用户目录，看不到用户平时的登录状态和 Cookie。用户的实际用途是：说"想吃饭了"，Agent 去搜韩式拌饭、日本寿司、中式炒菜里便宜的餐厅，比较菜单和评价，留下前 n 个；偶尔在淘宝、唯品会、Temu 看商品。这些需要在用户平常用的浏览器里做。
- 限制：Chrome 136 起，在默认用户目录上远程调试端口会被忽略，所以在默认 Profile 里**读不到 DOM、也发不了 CDP 输入**。只能靠截图 + 系统的无障碍树 + 系统级鼠标键盘。
- 本机：Windows 11 家庭版，默认浏览器为 Chrome 156；模型为本机 Ollama `qwen3.5:4b`。
- 用户的任务大多是"搜索键值对"：一个键词对应 n 个值词，值是键就分叉，不是键就搜一次、留下标签页、标为叶子；搜的过程中按关联条件（如第一页 ≥80% 的结果都提到某个词、Yelp 收藏榜 / 消费榜第一是某家店或某道菜）增加新节点或新键，直到全部成为末端叶子。现有任务树只有"母任务 / 子任务"，没有键、值、叶子这些状态，也不能被人在运行中修改。
- 4b 模型设计不出这种任务树的初始形态，只能在运行中增减节点，所以测试用例与任务类型分不开：先准备两种——点餐相关（Yelp 等）和 Google 搜索变形金刚角色，必须在真实网站上跑。
- 本项目是低频、用户主动发起的个人浏览器助手，不是批量采集或反检测系统。

## 目标
- **G1 第三种驱动**：命令行、配置文件、面板三处可选桌面驱动；默认仍为 CDP。
- **G2 看得见**：把代理窗口截图和无障碍树合成和现在格式一致的页面状态，ver1 的描述调用、标注图、选编号、兜底拦截、内容抽取、验证码判定原样复用。
- **G3 动得了**：用系统级鼠标（沿用轨迹模块）、滚轮、左右键、双击、键盘完成现有全部工具，动作后重新观察并判断是否生效，回到原有决策循环。
- **G4 人始终在环**：人一碰鼠标键盘就暂停；验证码、登录、改账号状态的点击、提交表单都暂停交给人；下单支付照旧硬拦截。
- **G5 关联展开任务**：按任务类型定义展开一棵键值树，4b 在运行中判定增减节点，有次数上限；过程中能看到末端叶子与节点数的变化。
- **G6 人维护任务树**：运行中随时暂停、在电脑面板上改树、再恢复；这些操作下一章手机直接复用。
- **G7 能直接用**：命令行和面板选一个任务类型、填几个参数就能发起；结果给出末端叶子清单、依据，点餐类再给出排好序的前 n 个。

## 功能需求

### A. 选择与窗口
- **F1 驱动选择**
  - 配置文件、命令行、面板设置页都可以选"桌面"驱动；命令行优先于配置文件；面板有任务运行时不能切换。
  - 桌面驱动只支持 Windows。所需依赖没装、或不是 Windows、或默认浏览器不是 Chrome 时，给出明确的中文提示（含处理办法）并退出，不回落到其他驱动。
  - 要求无界面运行时，提示"桌面驱动只能有界面运行"并按有界面运行。
  - 规则决策和大模型决策都能接桌面驱动；不保证现有规则用例在桌面驱动下全部命中（规则依赖 DOM 字段，无障碍树字段不完全一样）。
- **F2 代理窗口**
  - 任务开始时，用用户默认 Chrome 和默认 Profile 新开一个窗口（不加任何特殊启动参数、不另指定用户目录），登录状态和 Cookie 与用户平时一致；Chrome 已在运行或没在运行都能用。
  - 识别并记住这个窗口；窗口位置与大小可配置，每次动作前确保它在前台、未最小化、未被别的窗口挡住。
  - 只在代理窗口里操作；用户已经打开的其他窗口和标签页一律不碰。
  - 任务中途代理窗口被关掉，任务结束并记录"代理窗口已关闭"；任务结束后窗口保留给用户看。

### B. 读页面
- **F3 截图**
  - 只截代理窗口的网页内容区，不截整个桌面、不截其他窗口。
  - 处理 Windows 显示缩放（100%、125%、150% 等）和窗口位置：截图像素、屏幕坐标、页面坐标之间的换算比例写进记录；对上层统一为页面坐标，与现有约定一致。
- **F4 无障碍树读元素**
  - 从无障碍树读出网页内容区的元素，填成和现有元素清单一致的字段：角色、名称、显示文字、链接地址、输入框当前值、是否可用、位置框、是否在视口内；Chrome 自身的界面（地址栏、标签栏、书签栏、菜单）不进元素清单。
  - 密码框单独标出；密码框的值不读、不记录。
  - 网址从地址栏读，标题从窗口或文档读；正文从无障碍树的文字汇总，按现有规则截断。
  - Chrome 第一次被读时可能需要一点时间才开启无障碍支持：读取有超时，超时或读到的可用元素过少时转网格兜底（F5），并记录原因。
  - 遮挡判断：在元素中心点向系统查询"这里最上面是谁"，与元素本身不符即判为被遮挡。
- **F5 网格兜底**
  - 当整页或某块区域无障碍树读不到可用元素（如 canvas 绘制的按钮）时，在截图上叠一层带编号的网格，模型选格子编号，点击格子中心。
  - 网格点击在记录里标为"网格定位"。
  - 点击前在落点重新查询无障碍树：查到元素就按该元素照常走兜底拦截与需确认判断；查不到元素时，这次点击按"需确认动作"处理（F9）。

### C. 动作与观察
- **F6 动作**
  - 现有全部工具在桌面驱动下可用：点击、新标签页打开、输入、按键、滚动、后退、读文本、读链接、抽取，以及任务树类工具。
  - 鼠标：系统光标真实移动，沿用现有鼠标轨迹模块（平滑、可控、落点在目标框内），支持左键、右键、双击；滚轮滚动。
  - 新增"右键点击"工具：弹出的右键菜单项从无障碍树读出，下一步可以选。
  - 键盘：单键、组合键；输入中英文混合文本，结果与给定文本逐字一致，不依赖当前输入法状态。
  - 导航、后退、前进、刷新通过浏览器快捷键完成；"新标签页打开"用 Ctrl+点击或中键，打开后自动跟随到新标签页。
- **F7 观察与验证**
  - 每个动作后等待页面稳定：连续截图在设定时长内基本不变，且浏览器不在加载中；有总超时，超时返回"超时"及原因。（没有网络请求列表，这是与 CDP 驱动的已知差异。）
  - 稳定后重新截图、重读无障碍树，按截图差异、元素指纹、网址变化判断动作是否生效，结果按现有格式回传决策方。
  - 决策循环不变：观察 → 决策 → 执行 → 验证 → 下一步；重复动作检测、步数上限、崩溃（窗口失去响应）处理照旧。

### D. 人在环中
- **F8 人工输入即暂停**
  - 运行中区分人工输入和注入输入；检测到人工输入（鼠标移动、点击、滚轮、按键）立刻暂停：正在进行的鼠标轨迹中止，不再发出后续输入。
  - 程序自己的注入输入不会触发暂停。
  - 两种恢复方式都支持：在面板（或命令行）点"恢复"；或人停手超过 N 秒后自动恢复（N 可配置，设为 0 表示只能手动恢复）。
  - 恢复后一律重新截图、重读页面，不沿用暂停前的页面状态；暂停期间不计入任务时限。
  - 面板和命令行都能随时暂停、恢复、取消任务。
- **F9 需确认与转人工**
  - **验证码 / 人机验证**：沿用现有判定（改为基于截图描述与无障碍树），暂停转人工，处理完继续。
  - **登录、密码、短信验证**：遇到登录页、密码框、验证码输入框时暂停转人工；Agent 无论哪种决策方式都**永远不往密码框里输入**。
  - **会改账号状态的点击**：加入购物车、收藏、关注、写评价、发消息、预订等，按关键词清单识别（中英文，可在配置里增删），暂停等用户"允许一次 / 拒绝"。
  - **提交表单**：搜索框以外的表单提交（填地址、填资料等）先确认。
  - 允许一次：只执行这一次动作；拒绝：不执行，把"用户拒绝"作为结果回传决策方。等待确认期间不计入任务时限。
  - **下单、支付**：照旧硬拦截，不能放行、不能整体关闭。
  - 需确认判断对桌面驱动默认开启；对 CDP、Playwright 默认关闭（可在配置里打开），保证现有行为不变。
- **F10 窗口外与系统对话框**
  - 所有注入的点击坐标都必须落在代理窗口网页内容区内，否则拒绝执行并记录。
  - 出现系统对话框或浏览器自身弹框（文件保存、打印、权限请求、下载确认等）时暂停转人工，不去点它。

### E. 关联展开任务
- **F11 任务类型定义**
  - 一份任务类型定义写明：初始键值组；起始词；搜索方式（在哪个网站搜、搜索词怎么拼，如只搜值、或"键 + 值"）；候选词从页面哪里找（如右侧相关搜索、结果标题、排行榜，可以多处）；关联条件（自然语言描述，加可调参数，如"第一页 ≥80% 的结果提到"里的 80%）；次数上限（默认 120）；保留标签页上限（默认 30）；输出方式（末端叶子清单，或点餐类的抽取字段与排序依据）。
  - 定义不合法（缺起始词、起始词不在任何组里、参数越界等）时启动前报错，写明哪一项不对。
  - 本章提供两份定义：**点餐**（在韩式拌饭、日本寿司、中式炒菜等品类里找便宜的餐厅，关联条件含"收藏榜 / 消费榜第一的店或菜记下保留"）和**变形金刚角色**（Google 搜索）。两份都在验收前由用户与 Claude 共同编写。
- **F12 展开规则**
  - 节点状态：待查、键（分叉）、暂定叶子、末端叶子、已删除。
  - 从起始词开始：搜索当前词；对它的每个值——值本身是键，则分叉、展开它的值；不是键，则搜一次，按 F13 判定。
  - 顺序：按组的先后，组内按值的先后；运行中新建的键排到当前组之后（例：跑完 movie 组再看新建的 decepticon 组）。
  - 同一个词出现在多个键下面时，**每次出现都单独搜索和判定**，不复用上一次的结论。
  - 搜完一个值后：没有满足关联条件的新连接，定为末端叶子；有，则按 4b 的判定增加节点（挂到已知键下，或以被搜的词为新键，如搜 decepticon 发现 80% 在说 megatron，建出 `decepticon <megatron>`）。新加的节点按同样规则继续。
  - 结束：全部未删除的值节点都是末端叶子，且没有待查节点。
  - 保留标签页：定为末端叶子的节点保留它的搜索结果标签页；变成键或被删除的节点，标签页关掉；超过保留上限就只记录不再保留。所有搜过的页面都在记录里有网址和截图。
  - 每一次搜索或阅读作为一个子任务交给现有决策循环执行（同样受兜底拦截、需确认、人工输入暂停约束），结果回到展开树。
- **F13 4b 判定**
  - 每次搜索或阅读后，4b 拿到：当前页面（标注图、元素清单、正文摘要）、当前节点与它所在的键、整棵树的摘要、任务类型定义里的候选词来源和关联条件。
  - 4b 回答以下之一或组合：给某个已知键加值、以当前词建新键并加值、把当前节点定为末端叶子、删除当前节点（写明原因）。每项都要写理由，并指出页面上的依据元素。
  - 程序只做两项检查：加入的词必须能在所指元素或正文里查到（查不到就拒绝该项，记"无依据"）；操作必须是上面允许的几种。除此之外以 4b 的判定为准。
  - 4b 回答不合格式时按现有重问机制重试；仍失败则当前节点保持暂定叶子并记录原因，继续下一个。
- **F14 次数上限**
  - 无论节点如何增减，消耗达到上限（默认 120）就停下，任务进入"等待决策"，不自行结束、不自行续跑。
  - 剩余次数在面板上实时显示；沿用按域名的最小访问间隔。
- **F15 人工改树（电脑面板）**
  - 运行中随时可以暂停，暂停后在面板上改树，再恢复；达到上限的"等待决策"也用同一套操作。
  - 面板显示整棵树：每个节点的状态、所在的键、搜索次数、4b 的理由与依据、来源（初始 / 4b 新增 / 用户修改）；并显示末端叶子数、节点总数、已用次数随时间的变化。
  - 可做的操作：结束并输出结果；再给 N 次继续；删除节点；把节点改成末端叶子、或改回待查；加一个键值组；之后恢复运行。
  - 每次修改都记录（谁改的、改了什么、什么时候）；恢复后从修改后的树继续，不回滚用户的修改。
  - 这些查看与修改通过面板服务对外提供，下一章手机端直接复用。
- **F16 发起与结果**
  - 命令行和面板各提供一个入口：选一个任务类型，填它开放的参数（如地点、品类、留几个 n、预算、次数上限），即可开始；任务定义与参数随运行记录一起保存，可以再跑一遍。
  - 关联展开任务只能用大模型决策。
  - 结果：最终的树、末端叶子清单（每条附依据和来源网址）、保留的标签页列表、修改记录。
  - 点餐类另给：对末端叶子里**有依据**的餐厅，由程序按排序依据排序（如价位从低到高、同价位评分从高到低），输出前 n 个，附店名、价位、评分、链接；无依据的单独列出，不参与排序。价位能识别 `$`～`$$$$`、人均金额、价格区间并统一比较；识别不了的标"价位未知"，排在已知价位之后。

### F. 记录与面板
- **F17 记录**
  - 每步除现有内容外，增加：代理窗口截图、元素来源（无障碍树 / 网格）、坐标换算比例、本步注入的输入事件列表与轨迹、等待稳定的耗时与结果。
  - 每次任务记录：人工输入暂停（开始、结束、恢复方式）、需确认请求与用户回答、转人工记录。
  - 关联展开任务另记录：每次消耗对应的节点、4b 的原始回答与判定、被拒绝的项及原因、树的每一次变化（可按时间回看树的演变）、用户的修改。
  - 报告里能看到上述内容；密码框的值任何地方都不记录。
- **F18 面板**
  - 驱动下拉框有"桌面"；状态区显示当前步骤、暂停原因、待确认的动作和"允许一次 / 拒绝"按钮、恢复与取消按钮。
  - 预览：桌面驱动下用代理窗口的定时截图做缩略预览；预览上的手动点击输入在桌面驱动下不提供（用户可以直接操作真实窗口）。
  - 面板的这些状态与操作通过面板服务对外提供，供下一章手机端复用。

## 非功能需求
- **N1 向后兼容**：不选桌面驱动时一切行为不变；`pytest`、ver0 一键验收（CDP、Playwright）、ver1 一键验收、面板验收结果不变。桌面驱动的依赖作为可选依赖，核心依赖不变。
- **N2 复用不重写**：决策、页面摘要与标注图、兜底拦截、抽取、验证码判定、任务树、记录、鼠标轨迹全部复用；桌面驱动接入现有驱动接口，上层只在"这个驱动没有某项能力"时按声明的能力处理，不判断具体驱动名。
- **N3 坐标统一**：驱动接口上的坐标一律是页面坐标；显示缩放、窗口位置、截图缩放的换算全部在桌面驱动内部完成。
- **N4 只在本机**：截图、无障碍树内容、模型输入输出都不离开本机。
- **N5 隐私**：只截代理窗口；截图时代理窗口被挡住就先拉到前台再截，不把别的窗口内容存进记录；密码值不读不存。
- **N6 边界**：鼠标轨迹只用于平滑、可见、可控的操作；不改浏览器指纹、不隐藏自动化痕迹、不自动过验证码、不自动登录；沿用按域名的最小访问间隔；一次只跑一个任务，有步数上限和关联展开的次数上限，到上限停下等人，不做批量采集。
- **N7 可测**：坐标换算、无障碍树到元素清单的转换、人工 / 注入输入区分、需确认判断、价位识别与排序、关联展开规则（用替身模型按预设回答）都能脱离真实桌面和真实网站单独测试。
- **N9 驱动无关**：关联展开任务与人工改树在 CDP、Playwright、桌面三种驱动下都能用。
- **N8 速度**（参考，不作硬门槛）：每步"截图 + 读无障碍树"中位数目标 ≤ 3 秒，实测写进报告。

## 不做的事
- 手机控制端（在手机上查看、改树、暂停恢复取消、确认）：下一章。平板：不做。
- 运行时让模型设计任务类型的初始形态；运行时调用云端模型。新任务类型靠用户与 Claude 在开发对话里写定义。
- 关联展开以外的新任务类型。
- 接管用户正在用的窗口或标签页。
- Edge、Firefox 等其他默认浏览器（只检测并提示）；无界面运行；多任务并发；多显示器下跨屏摆放（代理窗口放主显示器）。
- 桌面驱动下的网络请求列表、强制打开封闭 Shadow DOM、面板预览上的手动输入。
- 自动登录、填密码、填短信验证码；下单、支付。
- 规避人机识别、自动过验证码、批量采集。
- 模型直接报像素坐标（只有网格兜底选格子）。
- 现有全部规则用例在桌面驱动下逐条跑通。
- 淘宝、唯品会、Temu、Yelp 的硬验收（只试跑记录）。

## 验收标准

方式：**自动** = 脚本判定；**自动+目视** = 脚本判定后人看一眼；**人工** = 需要用户亲手操作。桌面驱动的自动验收会真实移动鼠标，运行期间用户不碰电脑。

| AC | 对应 | 方式 | 验收内容 |

| AC1 | F1、N1 | 自动 | 默认配置仍是 CDP；配置或命令行选桌面驱动而依赖缺失时，看到中文提示并以非零状态退出；要求无界面时提示并按有界面运行；面板能选"桌面"，任务运行中切换被拒 |
