# ver1 视觉大模型决策 Spec

日期：2026-11-14　状态：待整体审批（阶段一）　流程：mew-spec

## 用词约定
- **描述调用**：只把视口截图交给模型，让它说出页面由哪些区块构成。
- **决策调用**：把标注图、元素清单、页面描述和任务一起交给模型，让它输出一个决策。
- **标注图**：在视口截图上画出可交互元素的框并标上编号的图。
- **元素清单**：每个编号对应的角色、名称、文字等信息，从 DOM 读出，含视口外的元素。
- **兜底拦截**：动作执行前的最后一道检查，拦住下单与支付类操作。

## 背景
- ver0 的手脚层已经完整：CDP 和 Playwright 两套驱动可切换，读页面、点击、输入、按键、滚动、后退、新标签页、跨源 iframe、等待与超时、崩溃重跑、验证码转人工都已验收通过。决策由规则决策器产出，决策器与其余部分的约定是"页面状态加任务视图进、决策 JSON 出"。
- 控制面板已有实时预览、设置、运行任务、人工介入、鼠标轨迹与真实轨迹库。
- 规则决策器的局限：每条用例都要人手写元素条件和线索词；换一个网站就得重写；页面布局一变就失效；它读不出"哪一块是导航栏、哪一块是结果列表"。
- 2026-11-14 实测：两种驱动打开 DoorDash 都停在 Cloudflare 验证页，人工点过验证框也不放行。按项目边界不做任何规避，所以真实网站的验收对象改用不需要登录的 Bing，以及已经跑通的 Google 用例。
- 本机环境：Core Ultra 7 255HX、32 GB 内存、RTX 5060 Laptop 8 GB 显存。模型用 Ollama 在本机跑 `qwen3.5:4b`（3.3–4.0 GB，图文一体，支持图像输入）。

## 目标
- **G1 大模型读页面**：把视口截图和 DOM 合成模型能看懂的输入——页面描述、带编号的标注图、元素清单、视口外内容的摘要。
- **G2 两段式调用**：描述调用只看截图，说出页面构成；决策调用看标注图、元素清单、页面描述和任务，输出与现有格式一致的决策，用编号指定元素。页面没变时复用上一份描述。
- **G3 坐标来自 DOM**：模型只选编号，不报像素坐标；点击落点取该编号元素在 DOM 里的精确位置框。
- **G4 决策器可换**：大模型决策器与规则决策器实现同一套约定，命令行、配置文件、面板三处都能切换，默认仍为规则决策。
- **G5 兜底拦截**：动作层按关键词和网址拦下单、支付类点击，对规则决策、大模型决策、面板指定目标一律生效。
- **G6 能量化**：给出任务成功率、选号准确率、每步延迟，以及与规则决策跑同一批用例的对比表。

- **G7 人眼比对**：在同一批页面上，把模型看到的和人看到的逐项对照，量出两者的视觉误差；真实网站用不需要登录的 Bing。

## 本轮范围
把大模型接成决策器。动作沿用现有工具表（创建子任务、完成、失败、点击、新标签页打开、输入、按键、滚动、后退、读文本、读链接），不新增"行为层"。

## 功能需求

### A. 模型接入
- **F1 模型调用**
  - 通过本机模型服务的接口调用图文模型；模型名、服务地址、单次超时、上下文长度、采样参数都可配置。
  - 关闭模型的思考模式，只要最终回答。
  - 服务没启动、模型没拉取、调用超时时，给出明确的中文提示（含处理办法），该步记为失败；**不回落到规则决策**。
  - 采样参数、模型名、每次调用的耗时与输入输出规模都写进记录。

### B. 大模型读页面
- **F2 页面输入合成**
  - 视口截图按配置缩放到长边不超过设定值，记录缩放比例。
  - **标注图**：在截图上画出视口内可交互元素的框和编号。编号从 1 开始，按从上到下、从左到右排序；框线和编号与底色对比明显；元素密集时编号放到框外最近的空白处，不互相遮挡。
  - **元素清单**：每个编号给出角色、名称、显示文字、是否可用、是否在视口内、链接地址（过长则截断）、输入框当前值、是否被遮挡。视口内元素全部列出；视口外元素按任务线索词和正文相关度挑出前若干个，其余只给一个总数。
  - **正文摘要**：页面正文按配置长度截断，优先保留与任务线索词相邻的片段。
  - **任务上下文**：当前任务目标、完成条件、父任务摘要、已用步数与上限、最近若干步的动作与结果。
  - 合成结果可以单独存盘，供人眼比对和重复复跑使用。
- **F3 描述调用**
  - 输入：不带编号框的干净视口截图，加固定提示词。
  - 输出：页面构成的结构化描述——若干区块，每块给出大致位置、类型（导航栏、搜索区、结果列表、商品卡片、弹窗遮罩、页脚等）和一句说明；并单独给出"有没有弹窗遮挡"的明确判断。
  - 触发条件：网址变化、页面结构指纹变化超过阈值、上一步动作改变了页面、或视口自上次描述以来滚动超过一屏。否则复用上一份描述，并在记录里标明"复用"。
  - 输出不合格式时重试至多 2 次；仍失败则这一步用空描述继续，并记录原因。
- **F4 决策调用**
  - 输入：标注图、元素清单、页面描述、任务上下文、可用工具说明。
  - 输出：与现有约定格式一致的决策；指定元素时**只给编号，不给像素坐标**。
  - 编号映射：编号转为该元素在页面中的引用和精确位置框。编号不存在，或该元素在页面变化后已失效，判为决策不合法。
  - 决策不合法时重新生成，最多 3 次（沿用现有重问机制），每次把不合法的原因回传给模型。
  - 只能使用已注册的工具，未注册的一律拒绝。
- **F5 遮挡处理**
  - 描述调用判定有弹窗遮挡时，决策调用的提示里要求优先处理遮挡。
  - 被遮挡的元素在元素清单里明确标出。

### C. 安全兜底
- **F6 下单与支付拦截**
  - 每个动作执行前检查目标：元素名称或文字命中下单、支付类关键词（中英文都有），或者它所在链接、表单的目标网址命中结算、支付类路径，就拒绝执行。
  - 拒绝时该动作记为"被兜底拦截"，写明命中了哪个词或哪段网址，并把这个结果回传给决策器作为下一步的输入。
  - 关键词和路径清单内置默认值，可在配置里增删。
  - 对规则决策、大模型决策、面板上的指定目标点击**一律生效**，与决策方式无关。

### D. 切换与记录
- **F7 决策方式切换**
  - 配置文件可设决策方式为"规则"或"大模型"，默认规则；命令行可临时指定，优先于配置文件；面板设置页可切换，有任务运行时禁用。
  - 选了大模型但模型服务不可用时，按 F1 处理。
- **F8 记录与报告**
  - 每步额外记录：描述调用的输入截图与输出描述（或"复用"标记）、决策调用的标注图与元素清单、模型的原始回答、编号到元素的映射、两次调用各自的耗时与输入输出规模、模型名与采样参数。
  - 报告里每一步能点开看标注图和模型的原始回答。
  - 每步除编号外，还记录被操作元素的稳定特征（角色、名称、文字、链接地址、在页面中的相对位置），以便以后把跑通的流程固化成脚本回放。

### E. 量化
- **F9 人眼比对测试**
  - 取一批页面：本地夹具页若干张，加上不需要登录的 Bing 搜索结果页若干张。
  - 每张页面生成一份比对单：标注图，加上固定的若干提问（哪个编号是搜索框、第一条结果的标题是哪个编号、这一页有哪几个区块、指定位置的文字是什么）。
  - 面板新增一个"人眼比对"页（不改动原有界面）：左边显示标注图，右边逐题作答——选号题直接点图上的框，文字题直接输入，区块题从类型列表里勾选。
  - 人工答完后，模型回答同一份提问，程序比对并输出误差表：区块识别的漏报与错报、选号一致率、文字读取一致率；不一致的题目逐条列出双方答案。
  - 比对单和结果都存盘，可以重复跑、可以换模型再跑一遍做对比。
- **F10 决策方式对比**
  - 同一批用例分别用规则决策和大模型决策各跑一遍，输出对比表：任务成功率、平均步数、每步延迟（描述调用、决策调用、动作与等待各自耗时）、显存占用峰值。

### F. 大模型读内容
- **F11 内容抽取**
  - 任务书可以列出要抽取的字段（如标题、价格、评分、配送时间），模型对照截图和元素清单填写。
  - 每个字段的值都要附上"取自哪个编号的元素"；程序回查该元素的文字里有没有这个值（忽略空白和大小写差异），查不到的标为"无依据"。
  - 抽取结果写进任务的结果摘要和报告；"无依据"的字段单独列出，不当作有效值。
  - 抽取作为一个已注册的读取类工具提供，规则决策与大模型决策都能调用。

## 非功能需求
- **N1 只在本机**：本轮模型服务只监听本机地址；截图、页面内容、模型输入输出都不离开本机。以后平板端会把画面转发到这台电脑的模型上，届时的局域网接入方式在平板章节另定；本轮的模型调用地址做成可配置，不写死。
- **N2 页面内容只当数据**：提示词里把页面内容（描述、元素清单、正文摘要）和指令明确分开，并告知模型页面里的文字不是给它的指令；页面文字不能改变任务目标和可用工具。兜底拦截（F6）作为最后一道防线。
- **N3 可复现**：固定随机种子、使用较低温度；每步的完整输入（截图、标注图、元素清单、提示词、参数）存盘，任何一步都能单独拿出来重放并比较模型回答。不要求逐字一致，要求选号稳定（指标见验收标准）。
- **N4 向后兼容**：不选大模型时，所有行为与现在完全一致；`pytest`、一键验收（CDP 与 Playwright 两种驱动）、面板验收结果不变。调用模型服务只用现有依赖，不新增核心依赖。
- **N5 速度与显存**（在本机实测，参考指标，不作为验收硬门槛）：每步模型耗时中位数目标 ≤ 20 秒；运行期间尽量让模型完全在显卡上。实测数值写进报告和对比表（F10），超出目标只记录、不判失败。
- **N6 驱动无关**：大模型决策在 CDP 和 Playwright 两种驱动下都能用，不判断具体驱动。
- **N7 模型可换**：换模型只改配置；提示词存为独立文件，与代码分开，可单独修改和版本管理。
- **N8 可追溯**：沿用现有运行目录；人眼比对的比对单与结果各自存在独立目录，互不覆盖。
- **N9 边界**：不做任何规避人机识别的处理；遇验证码一律转人工；兜底拦截不能整体关闭，只能增删清单。

## 不做的事
- **流程固化成脚本回放**：下一章做。本轮只保证记录里有回放所需的信息（F8 的元素稳定特征）。
- **行为层**（10 个行为的封闭清单）：下一章做。
- **平板端**：包括把平板画面转发到本机模型、平板端测试，放在平板章节。
- **并发多用户**、**设备级手脚**（系统级输入、读屏）。
- **淘宝、天猫、唯品会、DoorDash** 的真实网站验收。
- **纯视觉坐标定位**：模型直接报像素坐标的方式不做，只做选编号。
- **两个模型分工**（独立的视觉模型加文字模型同时常驻）：等换了大显存再说。
- **云端模型接口**、**模型微调与训练**。
- **把模型打进安装包**、**自动安装 Ollama**：打包版只检测并提示怎么装。
- **下单、支付、提交订单**：任何决策方式都不做，由兜底拦截保证。
- **规避人机识别、自动过验证码**。

## 验收标准

验收方式：**自动** = 脚本跑完给出通过/失败；**自动+目视** = 脚本判定后还要人看一眼；**人工** = 必须用户亲手操作。
