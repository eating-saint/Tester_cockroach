## 与 spec / plan / task 的偏离

| # | 原文 | 实际 | 原因 |
|---|---|---|---|
| 1 | plan 2.6：拦截检查 name / text / **context** | 不查 context | 商品卡片的 context 常含"Buy now"，查它会把点商品标题也拦掉 |
| 2 | plan 2.6 默认词含"结算""付款""支付" | 改成"去结算""确认支付""去付款""立即付款"等更具体的词 | 单字词会误拦"支付宝帮助""支付方式说明"这类链接 |
| 3 | spec F11：每个字段附"取自哪个编号的元素" | 也可省略编号，表示取自正文，程序到正文里回查 | 价格、评分这类普通文字不是可交互元素，清单里没有编号 |
| 4 | runner：extract 结果记"成功 + 错误" | 有无依据字段时记为失败 | v02 实测：模型把"成功但有错误"理解错，迷路 9 步 |
| 5 | task T28：v01 同时写规则版 rules | 规则版另存 `cases/v01r_shop_rule.yaml` | 规则决策拿不到页面上的值，没法有依据地 extract；两种决策要各自能通过 |
| 6 | 标注图编号牌只避开别的编号牌 | 优先也避开别的元素框 | 人眼比对实测：8 号牌压进 7 号框，模型把 8 号读成相邻文字；修后该页文字一致率 67% → 100% |
| 7 | 夹具 F17 | 加 `?size=` 参数 | 默认一页只比视口高约 50 px，测不了"视口外按线索词入选" |
| 8 | task T33：面板 `CompareJobs` 类 | 采集、模型作答作为 JobManager 的两种任务（`compare_capture`、`compare_model`） | 直接复用"同一时刻只做一件事"的互斥和进度显示 |
| 9 | 面板验收 P10 断言"视觉大模型 → 400（未接入）" | 改为"→ 200，未知决策方式 → 400"，选完切回规则 | ver1 本来就是要接入视觉大模型；旧断言描述的是 panel 一章时的状态 |
| 10 | 打包版首启：数据目录已有 cases / fixtures 就整个跳过 | 逐个文件补齐（不覆盖已有文件），并加 compare 比对集 | 否则老用户升级后拿不到 ver1 的用例、夹具和比对集 |

| 12 | 提示词 | 调了 3 轮，见 `docs/ver1/prompt_log.md` | 标签页标题误当商品标题；搜索区不单独列出 |
