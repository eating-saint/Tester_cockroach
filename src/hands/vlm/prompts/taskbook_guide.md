# 任务书写作指南（给 AI 用）

你要帮用户写一份"任务书"：一个 YAML 文件，交给本机的浏览器自动化程序按"关联展开"的方式运行。
程序只认这里列出的格式和积木。请严格按下面的说明写，只输出 YAML 本身（可以用 # 写注释），不要输出别的解释。

## 任务书在做什么

- 有一棵树：初始若干"组"，每组是一个**键**和它的若干**值**。从**起始词**开始，程序逐个处理树上的节点（词）。
- 处理一个节点 = 按顺序执行**节点流程**里的积木（同一条流程用于每个节点）。
- 流程里的"改树"积木决定树怎么长：把找到的词加为当前词的值（当前词成为新的键，之后会展开它的值）、加到某个已知键下、把当前节点标为末端叶子、删除当前节点。
- 一个节点的流程跑完、没有任何改树生效时，它是叶子。所有节点处理完，输出末端叶子清单，或按字段排序取前 n 个。
- 搜索、打开、翻页每次消耗 1 次；消耗达到上限就停下等人决定。

## 文件格式（format: taskbook/1）

```yaml
format: taskbook/1          # 必须原样写
name: 英文或拼音名           # 文件名，只用字母、数字、下划线、连字符
title: 给人看的标题
note: 说明（可选）
params:                     # 开放参数（可选）：运行时可改，在模板里写 {参数名}
  - {name: city, type: text, default: 北京, label: 城市}    # type：text / int / float / bool
groups:                     # 初始组：列表，每项「键: [值, 值]」
  - 键A: [值1, 值2]
start: 键A                  # 起始词：必须是某个组的键或值
limits: {budget: 120, keep_tabs: 30, trial_budget: 5}   # 总次数上限、保留标签页上限、试跑次数
flow:                       # 节点流程：积木列表，每项「积木id: {参数: 值}」，从上到下执行
  - search: {url: "https://www.bing.com/search?q={q}", query: "{word} {city}"}
output: {type: leaves}      # 或 {type: ranked, sort: ["价位:asc", "评分:desc"], n: 3, group_by: key, unknown: last}
```

模板变量：`{word}` 当前词，`{key}` 当前词所在的键，`{q}` 搜索词放进网址的位置（只能用在搜索网址里），以及 params 里声明的参数名。
**含 `{…}` 的值一定要加引号**，否则 YAML 会把它当成对照表。

## 清单

每个"产出清单"的积木用 `as` 给清单起名，后面的积木只能引用**前面**已经产出的清单名。
下面四张内置清单不用产出就能引用：`当前词`、`所在键`、`已知词`（树上所有键和值）、`已知键`。

## 常见错误

- 引用了后面才产出的清单，或忘了给产出清单的积木写 `as`。
- 搜索网址里没有 `{q}`；或者在 query 里写了 `{q}`（query 里用 `{word}`）。
- 把条件写成自然语言（如"如果提到很多次就加进去"）：程序不理解自然语言，条件要用 数比例 / 取名次 / 过滤 / 比较字段 这些积木算出一张清单，再用 改树 或 停 引用它。
- 用了不存在的积木或参数名；参数类型不对（数字写成文字、列表写成一个词）。
- 别名、译名（如中文名和英文名）会被当成两个不同的词：用 过滤 积木的 alias 别名表先归一。
- 起始词不在任何组里。
